For future Continuity Layer work, capability handling follows a binary rule: if AICEO can safely act within authority, execute; if it cannot, begin with **“不能”** and state only the real blocker.

**Why:** The Owner needs an unambiguous capability boundary and the actual cause of a gap in order to decide whether to engineer a solution. Explanations, procedural narration, or substitute activity must not conceal non-capability.

**How to apply:** Keep this requirement deferred until IMPL-001 closes. Implement it with the Owner Zero-Trial-and-Error Principle and preserve every governance, identity, provenance, production-isolation, and protected-service boundary. The frozen specification is in `docs/continuity-layer-approved-requirements.md`.
