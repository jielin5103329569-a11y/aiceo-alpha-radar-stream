---
name: Pre-classification memory inbox
description: Durable rules for preserving valuable ideas before scientific Memory OS classification and migration.
---

High-value Owner ideas may be preserved before scientific classification only as immutable, unverified, non-operational Inbox records. Preserve original semantics, source context, observed time, non-authoritative future destination hints, and DB-owned provenance hashes.

Inbox records are not facts, decisions, production rules, governance rules, retrieval inputs, promotion candidates, or independent validation. A sealed manifest binds the accepted seed set and raw semantic digests; runtime callers cannot add or rewrite entries outside an explicit migration.

Future scientific migration is deferred until classification, authority, provenance, epistemic-state, lifecycle, and independent-validation mechanisms are ready. One origin may be split across Decision, Knowledge, Experience/Learning, Collaboration, and Project/Roadmap memory, but every formal descendant must retain the origin Inbox ID, origin hash, and exact source/context/time lineage. No automatic promotion is allowed.

**Why:** Premature classification destroys nuance and can turn valuable exploratory thought into false authority, while unstructured temporary storage loses provenance and continuity.

**How to apply:** Treat the Inbox as a sealed provenance layer only. Do not use it for runtime decisions or retrieval. When the scientific migration module is explicitly started later, require Owner-approved migration, independent validation, origin-link verification, and append-only descendants while leaving the original Inbox record unchanged.
