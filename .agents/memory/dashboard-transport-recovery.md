---
name: Dashboard transport recovery
description: Preserve live dashboard state across SSE interruptions without allowing an old stream message to hide successful REST recovery.
---

The dashboard must use one shared “last successful status” projection for all verified status transports. Each API process issues a unique `statusEpoch` and strictly increasing `statusRevision` values inside that epoch. Accept a replacement only when it has a higher revision in the same epoch, or when a current REST response authoritatively establishes a new epoch after restart; record the replaced epoch as retired. `lastUpdatedAt` remains market-event time only and must never order dashboard snapshots. SSE is preferred for timeliness, but a successful newer REST fallback must be allowed to replace an older SSE snapshot while the stream reconnects. Retain the last verified snapshot only when neither transport has a newer successful result. A page reload may seed epoch selection from the raw last accepted snapshot, but it must render only a stale, alert-gated projection until a post-mount REST response confirms a coherent `scanId`; unconfirmed query-cache data is never renderable.

**Why:** Giving SSE its own permanent rendering precedence makes an interrupted stream mask a recovered API, leaving operators with stale data despite a working fallback path. Market-event time can remain null or unchanged during quiet markets, recovery, and connection/error transitions, so using it as a snapshot version can permanently hide newer operational state. A process-local sequence can reset after restart, so a version alone cannot safely distinguish a recovered server from a delayed old stream.

**How to apply:** When adding a new status transport, write validated responses through the epoch-and-revision shared projection and add regressions for both directions of out-of-order SSE/REST arrival, unchanged/null market time with changed connection or error state, and a low revision from a newly restarted epoch followed by delayed old-epoch messages. Only REST may establish an unseen epoch; reject all messages from retired epochs. On visibility, focus, pageshow, or online recovery, coalesce duplicate lifecycle signals, fetch REST immediately, then reopen SSE after epoch confirmation. Browser-link uncertainty may gate alert handoff but must not rewrite server-verified market freshness or produce a backend-down banner before REST actually fails. Treat browser transport state as presentation/diagnostic state, not as authority to override a newer verified snapshot.
